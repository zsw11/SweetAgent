同 title 不同内容、两次都要保留？——当前实现会丢历史
重灌 v2 → 旧 v1 去哪了？| 三个典型场景 + 三个改进方案 | 示意
什么时候会"同 title 不同内容、都要保留"？
① 版本演进：SOP v1→v2→v3，合规要留历史（"当时规定是什么"） ② 跨市场同名：「广告SOP」US 版 vs EU 版 ③ 定时抓取快照：平台规则 FAQ 每天变，历史可对比
① 当前行为（先删后建）
重灌 title='广告SOP' v2 时：
DELETE WHERE title='广告SOP' ──→ v1 被删（CASCADE 清 chunks/embeddings）
INSERT v2 → 库里只有 v2
v1 永久丢失 ✗
为什么现在能接受：种子文档是"人工修正重灌"场景（改错了重灌=纠错），不需要历史；但如果知识库接入飞书/网页/定时抓取，这就是数据丢失缺陷
② 软删除（改动最小，一行）
DELETE → UPDATE status='archived'，再 INSERT 新版（active）
检索本来就有 d.status='active' 过滤 → 历史版存档、不被召回，审计可查
③ 版本键（语义最清晰）
唯一键 (title, department, brand, market, version) → v1/v2 并存
检索 ORDER BY version DESC LIMIT 1 取最新；表已有 version 字段，但当前幂等键没用它
④ 审计/快照表（最重）
删除前把旧行复制到 knowledge_documents_history（doc_id/title/content_hash/archived_at）
与记忆系统的 memory_change_log 同思路：旧值不原地覆盖，独立审计表可追溯
