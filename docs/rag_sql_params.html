问题文本怎么进 SQL？相似度范围是多少？%s::vector 怎么理解？
三问一图：向量参数流 + 距离/相似度映射 | 示意
① 为什么 SQL 里看不到问题原文？——它先变成了向量
「公司的绩效制度是什么？」
→
embed_query()
→
[0.001, 0.002, ...] 1536 维向量
→
作为 %s 传给 SQL（param[0] / param[2]）
核心：向量检索比的是向量距离，不是文本本身——所以 SQL 里只有向量数组，没有问题文字。 对比：关键词检索（ILIKE）的 SQL 里就有原文词：%绩效% %制度%——因为 ILIKE 是字符匹配，必须用原文。
② 相似度范围：余弦距离 [0,2] → 相似度 [-1,1]
距离 = 0（完全相同）
距离 = 1（正交/垂直）
距离 = 2（完全相反）
sim = 1.0
sim = 0.0
sim = -1.0
公式：similarity = 1 - (embedding1 <=> embedding2)
实际文本场景：embedding 多取非负权重 → 相似度几乎都在 [0, 1]
实测分布（本项目）：
· mock 向量：无关文本也常有 0.02~0.16 碰撞噪声 → min_score=0.20 的意义所在
· 真实 embedding：语义相关文本通常 0.5~0.9（"床垫市场" vs "床垫行业趋势" → 高分）
· 关键词兜底行 similarity 恒为 1.0（字面完全匹配，_normalize 里写死）
③ %s::vector 怎么理解？
c.embedding <=> %s::vector 拆两半：
%s = psycopg2 参数占位符（防 SQL 注入），运行时被 vector_to_sql(qvec) 生成的字符串替换：'[0.001,0.002,...]'
::vector = PostgreSQL 类型转换（CAST 的语法糖），等价于 CAST(%s AS vector)
为什么必须转：<=> 算子要求两侧都是 vector 类型；参数进来是字符串，不转就报错：
operator does not exist: vector <=> unknown
一句话：%s 是"值从哪来"，::vector 是"数据库把这个值当什么类型算"——没有后者，余弦算子根本不认识这个参数。
