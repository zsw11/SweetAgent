RAG 梳理地图：三段论 × 关键决策
一句话定义：把私域文档切成块 → 向量化入库 → 提问时按语义召回相关块 → 注入 LLM 生成答案（给 LLM 装"外挂记忆"）| 示意
阶段① 索引 Indexing
把知识搬进"可检索的仓库"
加载 → 切分
决策：切多碎？
本项目：段落优先（语义完整）+ 超长段落 500 字窗口 + 50 字重叠
为什么：太碎=上下文残缺，太大=噪声多
向量化
决策：用什么模型？多少维？
本项目：真实模型 text-embedding-3-small（1536 维）/ 无 Key 降级 mock
为什么：维度必须和表结构一致，模型可换接口不变
存储
决策：存哪？带什么？
本项目：pgvector（vector(1536)）+ documents/chunks/embeddings 三表
为什么：与业务库同库、事务一致、幂等重灌
阶段② 检索 Retrieval
提问时把最相关的块捞出来
问题向量化 → 相似度
决策：用什么度量？
本项目：余弦相似度（`<=>` 算子，相似度=1-距离）
为什么：向量已归一化，余弦直观且是 pgvector 原生算子
过滤 + top-k
决策：怎么限定范围？取几条？
本项目：department 部门隔离（JOIN documents）+ top-k(5)
为什么：物流 Agent 永远只查物流知识，防跨部门污染
混合兜底
决策：向量召回不可信怎么办？
本项目：最高分 < 0.20 → 关键词检索（中文 2-gram，按命中数排序）
为什么：向量质量差时保底不漏检（双通道）
阶段③ 生成 Generation
把证据喂给 LLM 产出结论
注入什么
决策：把什么喂给 LLM？
本项目：title + content + similarity + method（命中来源可溯源）
为什么：只喂原文片段，不喂整库（token 成本 + 噪声）
怎么和 SQL 共存
决策：RAG 结果如何进入分析流程？
本项目：与 SQL 查询同构的 observations（columns/rows/...），analyze 无感
为什么：LLM 不用区分"这是查库来的还是检索来的"
谁决定查
决策：每次都要查知识库吗？
本项目：LLM plan 阶段自主选 knowledge 数据域（低成本 3ms）
为什么：问销售额不查知识库，问规则才查——省 token
④ 进阶变体（知道即可，本项目未做）与评估
Query 改写（把口语问题转成检索友好表述）
多路召回（向量 + 关键词并行，融合排序）
Rerank 重排序（用精排模型重排 top-50）
Agentic RAG（检索失败→改写→再检索的闭环）
本项目评估：verify_rag.py 8/8——命中正确文档 / 部门过滤无泄漏 / 兜底生效
