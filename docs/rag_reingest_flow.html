同 title、部分内容不同 → 重灌时 RAG 的处理链
以真实文档「库存预警与补货规则」（doc#13，3 chunks）为例 | 示意
① 重灌前（当前库）
documents: doc#13 库存预警与补货规则
chunks: chunk#51 / #52 / #53
embeddings: 51 / 52 / 53（1536维）
→
② ingest_document（同 title）
DELETE WHERE title=...
→ CASCADE 删光 doc#13 + chunk#51/52/53 + 3 个 embedding
旧内容全部消失（含被改掉的段落）
→
③ 全量重建（只留新版）
INSERT 新 doc（id 变成 #19）
重新切分：chunk 边界可能变（3 个变 4 个，id 全新）
重新向量化 → 新 embeddings（只有新向量）
重灌后 RAG 检索侧的影响：
✓ 检索只看到新版内容，不会新旧混合 ✓ 新改的段落立即生效（改库即生效） ✗ 被删/被改的旧段落从此不可检索（旧版永久丢失） ✗ 旧 chunk_id 全部废弃，引用旧 chunk 的缓存/日志失效 ⚠ 全量重算向量：重灌成本 = 全文重新切分 + 重新 embedding
本质：同 title 重灌 = 全量替换（upsert 语义），不是"合并差异"也不是"增量更新"——部分内容不同 → 整篇重建。
