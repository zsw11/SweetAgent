为什么 params 有 4 个参数？——SQL 里有 4 个 %s，位置一一对应
psycopg2 按位置绑定（positional binding）：参数顺序必须和 %s 出现顺序完全一致 | 示意
SQL（占位符按出现顺序编号）
SELECT c.id, c.document_id, c.chunk_index, c.content, d.title, d.source_type, d.department, d.brand, d.market, 1 - (c.embedding <=> ①%s::vector) AS similarity FROM knowledge_chunks c JOIN knowledge_documents d ON d.id = c.document_id WHERE c.embedding IS NOT NULL AND d.status = 'active' AND d.department = ②%s ORDER BY c.embedding <=> ③%s::vector LIMIT ④%s
params = [vector_to_sql(qvec), *params, vector_to_sql(qvec), top_k]
[0] 向量A（1536维）　←→ ① SELECT 算相似度
[1] 'company'　　　←→ ② WHERE 部门过滤
[2] 向量A（同一份）　←→ ③ ORDER BY 排序
[3] 5　　　　　　　←→ ④ LIMIT
注意：如果还传了 brand/market/document_type，过滤条件会在中间依次展开（params 变 5/6/7 个），顺序依然严格对应 SQL 中 %s 的出现顺序。
为什么向量出现两次（① 和 ③）？
ORDER BY 不能引用 SELECT 的别名：写 ORDER BY similarity 会报错 column "similarity" does not exist——排序必须重写完整表达式 c.embedding <=> %s::vector，自然要再传一次向量。这是 pgvector + 参数化的常见写法。
为什么用 %s 而不是字符串拼接？
psycopg2 参数化自动处理转义 → 防 SQL 注入（向量字符串/过滤值含特殊字符也不怕）； 拼接则存在注入风险。参数与占位符按位置匹配，不按名字。
