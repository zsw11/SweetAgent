当前检索决策树：向量为主，关键词兜底（降级式）
两路不是并行融合，是"向量不可信才换关键词"的择一通道 | 示意
① 向量检索（PGVector 余弦，top-5）—— 先跑，默认路径
② 最高相似度 < 0.20 ？
0.20 = "向量结果可信线"（mock 向量下无关文本也可能有 0.02~0.16 碰撞噪声分）
→ 否（≥0.20）：返回向量结果（confidence high/medium/low）
→ 是（<0.20）：向量不可信，换关键词通道 ↓
③ 关键词检索（2-gram 拆词 + ILIKE，top-3）—— 兜底通道
④ 关键词有命中？
→ 是：返回关键词结果（按命中词数排序，confidence high/medium/low）
→ 否（0 命中）：双通道都不可信 ↓
⑤ 返回空 + confidence=none → 下游显式回答"知识库未收录"，禁止编造
三种"混合检索"形态（面试区分）
① 降级式 fallback（本项目当前）
先向量，不可信才关键词；两路不同时返回，是择一通道
② 融合式 fusion（进阶，未做）
向量 + 关键词并行跑，用 RRF（倒数排名融合）/加权分数合并排序，两路证据共同决定
③ 级联式 cascade（进阶，未做）
向量召回 top-50 → Cross-Encoder rerank 精排取 top-5
为什么现在是降级式：改动最小 + mock 向量下向量分普遍偏低，关键词几乎总是常态路径；融合式（RRF）需要两路并行 + 分数归一化，是接真实 embedding 后的升级方向。
